Overview

What is TripGenie?

TripGenie is a full-stack AI-powered travel planning web application built as a school project. It allows users to plan trips end-to-end — from generating AI itineraries to tracking budgets, managing packing lists, setting reminders, pinning places on a map, logging journal entries, and checking live weather — all in one cloud-synced platform.

💡 School context: TripGenie was built entirely by the TripGenie Team as a school project. It is live at tripgenie.space with a real PostgreSQL database, real user authentication, and real AI integration.

Features

  • 🗺️Interactive Map — Leaflet/OpenStreetMap with custom pin-drop, fullscreen mode, saved to the cloud

  • 🧳AI Packing List — AI-generated and inline-editable before saving
  • 🔔Smart Reminders — priorities, categories, AI-suggested dates, done/undo
  • 📖Trip Journal — date-stamped entries with mood, saved to DB via JSONB metadata
  • 🏷️Trip Tags — preset + custom tags (Beach, Business, Family…) stored as TEXT[] in DB
  • 📅Calendar View — visual month calendar showing trips, itinerary events, and reminders
  • 🎙️Voice Input — speak trip details, AI extracts and auto-fills the form
  • 📄PDF Export — full trip summary exported via browser print API
  • 🔐Full Auth — email/password + Google OAuth 2.0, JWT, forgot/reset password
  • 🌙Dark Mode — full dark palette with deep #0a0c10 background
  • 📍Destination Autocomplete — Nominatim-powered with keyboard navigation
  • 📊AI Budget Insights — GPT analyzes spending patterns and gives saving tips

Request Flow

  1. User opens tripgenie.space

    Browser loads static files from Render's CDN. app.js initialises, reads JWT from localStorage, and calls GET /api/auth/me to verify the session.

  2. Authenticated API calls

    Every API call goes through apiFetch() which automatically attaches the Authorization: Bearer <token> header and handles 401 auto-logout.

  3. Backend processes request

    Express routes validate the JWT via the auth middleware, query PostgreSQL, and return JSON. Rate limiting runs before any route handler.

  4. AI requests

    The frontend sends a message to POST /api/assistant/chat. The backend calls the OpenAI API server-side (keeping the API key secret) and returns the reply to the frontend.

Database Initialisation

-- Run on your PostgreSQL instance:
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT,
  full_name TEXT NOT NULL,
  avatar_initials TEXT,
  avatar_url TEXT,
  preferred_currency TEXT DEFAULT 'USD',
  preferred_timezone TEXT DEFAULT 'UTC',
  provider TEXT DEFAULT 'local',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE trips (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  destination TEXT NOT NULL,
  cover_image TEXT,
  start_date DATE,
  end_date DATE,
  status TEXT DEFAULT 'upcoming',
  planning_pct INT DEFAULT 0,
  notes TEXT,
  itinerary JSONB,
  tags TEXT[] DEFAULT '{}',
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE budgets (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  trip_id UUID UNIQUE REFERENCES trips(id) ON DELETE CASCADE,
  total_amount NUMERIC NOT NULL,
  currency TEXT DEFAULT 'USD',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE budget_categories (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  budget_id UUID REFERENCES budgets(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  allocated NUMERIC DEFAULT 0,
  color TEXT DEFAULT '#068cdf'
);

CREATE TABLE expenses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  category_id UUID REFERENCES budget_categories(id) ON DELETE CASCADE,
  trip_id UUID REFERENCES trips(id) ON DELETE CASCADE,
  description TEXT NOT NULL,
  amount NUMERIC NOT NULL,
  spent_on DATE DEFAULT CURRENT_DATE,
  receipt_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE checklists (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  trip_id UUID REFERENCES trips(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  icon TEXT DEFAULT '📋',
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE checklist_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  checklist_id UUID REFERENCES checklists(id) ON DELETE CASCADE,
  label TEXT NOT NULL,
  is_checked BOOLEAN DEFAULT FALSE,
  sort_order INT DEFAULT 0
);

CREATE TABLE reminders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id) ON DELETE CASCADE,
  trip_id UUID REFERENCES trips(id) ON DELETE SET NULL,
  title TEXT NOT NULL,
  description TEXT,
  remind_at TIMESTAMPTZ NOT NULL,
  priority TEXT DEFAULT 'medium',
  category TEXT,
  is_done BOOLEAN DEFAULT FALSE,
  done_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE password_reset_tokens (
  user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  token TEXT NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL
);

-- View for category spending totals
CREATE OR REPLACE VIEW category_spending AS
  SELECT bc.*, COALESCE(SUM(e.amount), 0) AS spent
  FROM budget_categories bc
  LEFT JOIN expenses e ON e.category_id = bc.id
  GROUP BY bc.id;

API Reference

API Endpoints

Base URL: https://ui-production-e419.up.railway.app/api

All protected routes require header: Authorization: Bearer <token>

Authentication

POST /auth/register Create a new account

Body: { email, password, full_name }

Returns: { token, user }

POST /auth/login Sign in with email/password

Body: { email, password }

Returns: { token, user }

GET /auth/me Auth required Get current user profile
PATCH /auth/me Auth required Update profile

Body: { full_name?, preferred_currency?, preferred_timezone?, avatar_url? }

POST /auth/forgot-password Send password reset email

Body: { email } — always returns success to prevent enumeration

POST /auth/reset-password Reset password with token

Body: { token, password }

GET /auth/google Initiate Google OAuth flow

Trips

GET /trips Auth required List all trips. Query: ?status=upcoming
GET /trips/:id Auth required Get single trip
POST /trips Auth required Create trip

Body: { title, destination, start_date?, end_date?, notes?, cover_image? }

PATCH /trips/:id Auth required Update trip fields

Allowed fields: title, destination, cover_image, start_date, end_date, status, planning_pct, notes, itinerary, tags, metadata

DELETE /trips/:id Auth required Delete trip and all related data

Budget

GET /budget/:tripId Auth required Get budget + categories with live spending totals
POST /budget/:tripId Auth required Create or update budget total

Body: { total_amount, currency? }

POST /budget/:tripId/categories Auth required Add spending category

Body: { name, allocated?, color? }

POST /budget/:tripId/expenses Auth required Log an expense

Body: { category_id, description, amount, spent_on?, receipt_url? }

DELETE /budget/:tripId/expenses/:expenseId Auth required Delete expense

Checklists & Reminders

GET /checklists Auth required List checklists. Query: ?tripId=uuid
POST /checklists Auth required Create checklist

Body: { trip_id, title, icon? }

POST /checklists/:id/items Auth required Add item to checklist

Body: { label, sort_order? }

PATCH /checklists/items/:itemId Auth required Toggle checked or rename item

Body: { is_checked?, label? }

GET /reminders Auth required List reminders. Query: ?tripId=uuid&done=false
POST /reminders Auth required Create reminder

Body: { title, remind_at, trip_id?, description?, priority?, category? }

PATCH /reminders/:id Auth required Update or mark done

Body: { is_done?, title?, remind_at?, priority?, description? }

AI Assistant

POST /assistant/chat Auth required Send message to AI. Rate limited: 10 req/min

Body: { message, context? } — message max 8,000 chars

Returns: { reply }

The backend auto-detects intent (itinerary, packing list, budget, weather, tips) and applies appropriate system prompts and token limits.

Security

Security Measures

🔐

Password Hashing

All passwords hashed with bcrypt at cost factor 12 before storage. Plain text passwords are never stored or logged.

🎫

JWT Authentication

Stateless JWT tokens with 7-day expiry. All protected routes verify the token via the auth middleware. 401 responses trigger automatic client-side logout.

🚦

Rate Limiting

Global: 200 req / 15 min. AI assistant: 10 req / min. Auth routes: 20 req / 15 min. Prevents brute force and OpenAI credit drain.

🧹

Input Sanitization

Auth inputs trimmed and capped at max lengths (email: 255, password: 128, name: 100). AI messages capped at 8,000 characters server-side.

🔒

HTTPS

All traffic encrypted via TLS. Render enforces HTTPS on the frontend. Railway enforces HTTPS on the backend. Cloudflare adds an additional security layer.

🛡️

Email Enumeration Prevention

The forgot-password endpoint always returns the same success message regardless of whether the email exists, preventing user enumeration attacks.

🔑

API Key Security

OpenAI, Resend, and Cloudinary API keys are stored as Railway environment variables. They are never exposed to the frontend. All AI calls are proxied through the backend.

🗄️

Row-Level Security

All trip, budget, checklist, and reminder queries include user_id = req.user.id constraints — users can only access their own data.

Technical Decisions

Why Vanilla JS (no React/Vue)?

We chose vanilla JavaScript intentionally to demonstrate a deep understanding of the DOM, event handling, async/await, and state management without framework abstractions. The app manages complex state (trips, budgets, checklists, modals, editing sessions) entirely in plain JS — this is a harder approach that showcases fundamental web development skills.

Why PostgreSQL over MongoDB?

Travel data is highly relational — a user has trips, trips have budgets, budgets have categories, categories have expenses. Relational integrity (CASCADE DELETEs, foreign keys) is critical. We also use JSONB columns (itinerary, metadata) where flexibility is needed, giving us the best of both worlds.

Why GPT-4o-mini over GPT-4?

GPT-4o-mini provides excellent quality for travel planning tasks at a fraction of the cost of GPT-4. For a school project with real usage, cost control was important. The assistant route uses intent detection to dynamically adjust system prompts and token limits per request type — itinerary generation gets 2,500 tokens while quick tips get 400.

Why free APIs for maps/weather/currency?

Leaflet + OpenStreetMap, Open-Meteo, Frankfurter, and Nominatim are all production-grade free APIs with no API keys or rate limit concerns for reasonable usage. This keeps the project cost-effective and removes the risk of billing surprises during the project's demo period.

Why Render + Railway over AWS?

Render and Railway offer zero-config deployments from GitHub with automatic SSL, environment variable management, and free/low-cost tiers. For a school project, reducing DevOps overhead meant we could focus on features. Railway's integrated PostgreSQL also eliminated the need for a separate database host.

Data storage: DB over localStorage

All user data — itineraries, map pins, journal entries, trip tags — is stored in PostgreSQL, not localStorage. This makes the app genuinely cloud-synced: users get the same data on any device, in any browser. The only things in localStorage are auth tokens and UI preferences.

Challenges & Solutions

🧩

SPA without a router

Managing navigation, modals, and state across 15+ pages with no framework required careful global state design and event delegation.

⚡

Nominatim rate limiting

The geocoding API limits to 1 req/sec. Solved with an in-memory geocode cache and request debouncing on the autocomplete.

🔄

AI response parsing

GPT responses vary in format. Built robust regex parsers that handle clock emoji variants, different dash characters, and markdown artifacts.

🌙

Dark mode with third-party maps

Leaflet renders its own canvas outside our CSS. Solved with a CSS brightness/saturate filter on the tile layer and custom Leaflet popup styles.

🔐

Google OAuth callback

The backend receives the OAuth callback and must redirect to the frontend with the JWT token. Required careful URL encoding of user data in the redirect.

📦

JSONB metadata design

Storing map pins and journal entries in a JSONB column avoided new DB tables while keeping data cloud-synced. Required careful merge logic on updates.

Render Rewrite Rules

Since the app is a SPA served from static files, Render needs rewrite rules so that navigating to /app serves app.html:

/app         → /app.html      (Rewrite)
/login       → /login.html    (Rewrite)
/register    → /register.html (Rewrite)
/forgot      → /forgot.html   (Rewrite)
/reset-password → /reset-password.html (Rewrite)
/auth-callback  → /auth-callback.html  (Rewrite)
/terms       → /terms.html    (Rewrite)
/privacy     → /privacy.html  (Rewrite)
/*           → /app.html      (Rewrite — catch-all)

Deploy Process

# Any push to main triggers auto-deploy on both Render and Railway
git add .
git commit -m "feat: your change"
git push origin main

# Render deploys in ~30 seconds (static site)
# Railway deploys in ~2 minutes (npm install + node server.js)
